## UI、数据与生命周期合同

复用[概念图](../reference/RemoteHub_UI_Concept.png)的左侧导航、卡片/状态区域、连接对话框和会话工具栏。图中Linux设备、1080p60、带宽/延迟、NAT类别和“3个中继”均未成为当前实测产品能力；这些区域依赖真实数据，缺能力就显示不可用，不伪造0值或在线状态。

Rust是权限、会话与资源所有者；前端负责展示和用户动作，不能自授批准。拟议产品状态需区分idle、等待批准、协商、播放、停止中、已停止、失败；这些正式会话状态尚未接入；本轮仅增加只读IPC类型/错误与本机读取store，**没有新增Rust会话命令/字段**。现有Session状态与原生资源真值通过适配层映射，不能仅从video.readyState、按钮点击或GUI进度推断远端已授权。

单会话上限和取消代次由Rust所有者落实；UI重复开始或停止幂等，晚到IPC/事件丢弃并撤销相关资源。布局切换不自动发起配对；设备列表没有持久身份时为空态。信令状态、选路结果、媒体统计及清理状态独立显示。

关闭行为建议：无活动会话时，只有用户选择了托盘驻留才隐藏；否则退出。活动**实验**被关闭时先撤销/停止，再决定是否留空壳托盘；不后台继续采集。未来正式会话若需后台继续，须P2/P3明确授权合同和可见停止提示，P1不预先开放。明确“退出”始终停止本人会话、关闭订阅/任务/自建进程并报告实际清理，不杀无关用户进程。

## 安全与验证方案

- 保持普通构建实验feature默认关闭、原生同意和最小Tauri capability；前端无任意文件/命令执行权限，不从页面URL恢复有效票据。R06拒绝不可被产品状态映射成回退成功。
- 先做无网络fixture/单元：五页导航、空态、能力缺失、IPC拒绝、错误映射、迟到事件、重复操作、live/last_known/null、断订阅与托盘状态；fixture显式标识且与真实适配器隔离。
- 真实原生UI验证只启动UI，不默认采集；类型/格式/lint、默认及适用feature构建、Rust/clippy/集成与浏览器检查有独立结果。没有新媒体需求就不要求重复双机串流。
- 若某项IPC/生命周期确需合成视频或云验证，再提出最小范围和授权；真实桌面/输入、驱动/路由、阿里云不随P1 UI批准自动授权。实际统计/selected pair/ACK/释放仍须真实来源。
- 遇到资源残留、权限扩大、后端版本不符、过期操作有效、统计泄漏或历史回归，暂停相关任务并用普通提交回退；旧实验构建/证据作为可用基线，不重写历史。

## 三件套兼容怎样进入计划

P1-01先产出C0目标合同：仅管理现有WebRTC，还是必须与原生Foundation/V+直接互操作。后者需要独立原型授权及C1来源/许可核验；在可行性/单UI合同明确前，P1-02/03不能把兼容入口标可用。P1-04只设计经核验所需的薄边界，不预先编造第三方API、FFI或overlay实现。

默认WebRTC能力与未来兼容后端分别标识；EasyTier若引入是独立承载，不用其进程状态冒充P2P。受管理进程/可选组件版本、配对、统计、退出/崩溃、配置隔离和回滚是该原型必测项，见[ADR0015](ADR/0015-client-backend-and-compatibility-plan.md)。不从这份P1方案推断已经允许打包第三方、安装驱动或替换当前架构。
