# P0-05 双机验证操作

使用同一个P0-05优化程序，Windows x64 + WebView2。保持P004b成功的有线局域网、对端/本机IP、程序路径和现有网络策略；本轮不修改系统安全配置或防火墙。

关闭两台旧RemoteHub窗口，用本轮更新包同名exe覆盖原先成功目录，重新打开后核对P0-05标题。发送/被控端提供主屏视频，接收/控制端播放并自动发送模拟事件。每轮30秒，双方亲自勾选“视频及模拟坐标”并确认原生提示、使用新的临时配对码。配对码不发到聊天或日志。

1. 完整轮：保持接收端窗口可见，视频真正播放后自动20Hz发送100条模拟鼠标事件，另发一次ping。约5秒后检查发送100/ACK100、ping1/pong1、待确认0/异常0；发送端检查Rust接收100/写入ACK100。拖动发送端普通测试窗口，确认画面仍变化，让它自动结束。
2. 主动停止：重新配对，等100/100后点接收端停止（或发送端停止），等双方资源回收。不得自动恢复发送。
3. 关窗：重新配对，等100/100后直接关闭接收端窗口；发送端应提前停止、释放源/通道/PC。重开后不自动采集。
4. 网络中断：重新配对，等100/100后拔掉接收端网线，等待发送端租约到期并回收，再接回。允许显示LAN_LEASE_EXPIRED；不可接线后自动恢复。

发送计数来自B的DataChannel.send；接收计数来自A的OnMessage；A的ACK发送成功仅表示库排队，必须结合B.onmessage的ACK计数验收。面板的“未确认”表示pending，断线时不能直接说是丢失。每轮原生报告位于程序旁 `artifacts/private/p005`；B的final含浏览器真实control统计，A的source.control含原生通道事件和task_joined。

如果失败，先提供两端固定错误文字和统计，不提供配对码/完整SDP/桌面内容。协议负例（重复、错会话、超大、非法、超频）由无采集的真实本机SCTP集成与纯协议测试覆盖，必须与真实双机正常/中断轮分开报告。源码协议见CONTROL_V1。

没有实际鼠标/键盘输入、文件传输、云服务器或TURN功能。P005完成后停止扩展，等待审查。
