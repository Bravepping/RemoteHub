# P0-04b：两台 Windows PC 的局域网视频验证

**状态：双机媒体路径未实施、未实测；已实现独立签名信令原语。** P0-04a 的本机结果不能作为 P0-04 双机验收证据。见 [开发基线 §5、§11](RemoteHub_完整开发文档_v1.0.md) 和 [安全边界](SECURITY.md)。

## 允许实施的最小范围

- 两台本人授权的 Win10/11 x64 PC，同一个隔离的私有局域网。A 使用 DXGI / Media Foundation 实时采集并以 WebRTC 发送 720p30 H.264；B 只通过原生 Tauri WebView2 解码、播放和报告统计。仅前台、一次性限时、不允许无人值守。默认构建不提供入口，与 P0-04a 分开。
- **先实现设备授权，再允许真实桌面离开 A。** 实验最小依赖为 P2-01/04/05/06 的必要子集：本机 Ed25519 身份、DPAPI 保护私钥；双方现场人工比对安全码确认公钥，并保存完整受信公钥；只授权 `view_screen`。A 每次显示 B 的已确认身份，由原生界面明确批准；共享期间持续可见、可立即结束和撤销。不把 IP、短设备 ID、局域网或显式勾选当成身份凭据。
- 不需提前部署 P2 服务端。可通过本地可见界面手动交换**原生签名的**、短时有效 SDP 信令包；严格验证协议用途/版本、双端设备指纹、session ID、单次 nonce、过期时间、规范化 SDP 哈希和 DTLS fingerprint，answer 绑定同轮 offer；先验签、检查对端信任和重放，再设置远端描述。验收前不提供无签名粘贴 SDP、分发预共享通用密钥或自动信任入口。
- 在授权通过后才采集。运输层只允许获准的私网接口和同一实验网络内指定对端的 UDP host 路径；检查收发端真实选中的候选和地址。限制绑定和接收路径，不监听全部接口；默认不改系统/防火墙、不打开端口映射，不配置 STUN/TURN，无账号、远程输入、DataChannel 或公网信令。候选不可用、身份不符、未能核实选中路径时立即失败。
- 保留 P0-04a 的 RTP/AU 时钟、背压/清理和独立媒体统计；增加对端失联、同意撤销和网络范围变化时立即停止/回收的测试。只分享合成运动窗的脱敏证据；真实画面、原始 SDP、凭据、完整网络地址不提交。

## 已实现的离线前置组件

`crates/hub-webrtc/src/signed_signal.rs` 复用锁定的 `ring 0.17.14`：使用配对公钥验证 Ed25519、绑定精确 SDP 字节和 DTLS SHA-256 指纹、双方设备/session/用途、answer 对应 offer 摘要，并在本地核发限时且单次消费的随机 challenge。有效性同时受 UTC 和本机单调时钟限制。组件不联网、不持久化密钥、不提供导入或签名 IPC，不改变 P0-04a；内部签名输入不是产品序列化协议。集成时只可用本机配对存储的公钥和本机创建的接收 challenge。

`cargo test -p hub-webrtc --lib --locked signed_signal` 验证篡改、伪造、跨设备/跨 session、重复/过期、DTLS 指纹歧义，以及 offer/answer 成功验证。设备身份存储、配对、可见授权、传输接入及双机实测仍未完成。
