# P0-04b 双机实验操作说明

两台 Windows x64 电脑使用同一版本的 `remotehub-desktop.exe`，解压到可写目录；不需要安装 Rust、Git、Node。接收端需要 WebView2 Runtime，程序会实际检查 H.264 Baseline 解码支持。没有 Runtime 时使用微软官方安装程序补齐，不关闭系统安全拦截。

1. 两台电脑均保持解锁、接通电源、关闭自动休眠。首次让当前开发机作为发送端，另一台作为接收端。双方连接同一个有线局域网。
2. 仅发送端需要接收入站 TCP 48604 和动态 UDP。先用包内 `p004b-firewall.ps1 -Mode Inspect -Program <程序完整路径> -LocalIp <发送端IP> -PeerIp <接收端IP>` 查看范围，再在管理员 PowerShell 中用相同参数 `-Mode Install` 执行。规则只允许该程序、该本机IP和该对端IP，适用专用/域网络。测试完以 `-Mode Remove` 删除相同规则。脚本不关闭防火墙、不改网络类别。若是公用网络或受组织策略管理，先排查环境，不扩大放行范围。
3. 发送端启动程序，选“发送端”，填另一台IP，点“检测本机IP”并核对是有线网卡地址；时长 30 秒。亲自勾选本次同意，点“等待接收端连接”，亲自确认原生提示。此时还没有采集画面；显示的本轮配对码最多等待 120 秒，仅交给接收端，不发到聊天或日志。
4. 接收端选“接收端”，填发送机IP并检测/核对自己的IP，时长同为 30 秒。输入发送端配对码，亲自勾选同意、点连接并确认原生提示。开始真实连接与采集。认证成功后发送端关闭信令监听，不接受另一台电脑。
5. 第一轮让它自动结束；期间在发送端拖动普通测试窗口或播放非私人运动图案。接收端应实际看到变化。记录真实接收/解码/呈现帧、1280×720尺寸、指定对端UDP检查和资源回收结果。仅“已连接”不能算通过。
6. 后续每轮重新配对并确认：接收端主动停止、发送端主动停止、接收端播放中关窗、播放中拔掉接收端网线。拔线后应在租约超时和清理上限内停止发送；接回网线不会自动恢复采集。

统计保存在每台程序所在目录的 `artifacts/private/p004b/`，不含视频画面、IP、配对码、完整SDP。`progress` 是运行中快照；`native-final` 是原生任务结束状态；`final` 包含正常界面的浏览器关闭确认；`window-close` 只报告可观测的原生清理，不伪造关窗后的浏览器统计。发送端通过已认证控制连接获得接收端统计，接收端关窗后的缺失计数不补写。

故障：`LAN_LISTEN_FAILED` 检查端口占用/本机IP；`LAN_CONNECT_FAILED/TIMEOUT` 检查地址、有线链路及上述发送端规则；`AUTH_REJECTED/LAN_SIGNAL_FAILED` 重新生成一轮码并核对输入；`WEBVIEW_H264...UNAVAILABLE` 是实际浏览器能力不足；`BROWSER_SELECTED_OFF_PEER` 立即终止该轮并报告。不要发送配对码、原始SDP、桌面录像或设备ID。

本实验只验证单向视频。DataChannel、键鼠、文件传输、互联网穿透、TURN、长期稳定性、正式安装包仍未验收。
