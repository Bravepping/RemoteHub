# ADR 0014：Phase 0 最终证据、剩余风险与批准门槛

日期：2026-11-22；审查基线 main `7fde54e6d94f2eb9ef2697e437cccfd42f4f67c9`。状态：**本轮离线评审完成；R06 风险接受及 Phase 0 退出待用户正式决定**。不授权 Phase 1 实施或任何云端操作。

## 背景与增量

ADR0012 记录当时 E04 尚未批准、R06 新版未做双机的事实；ADR0013 及 P007B 决议随后接受了 E04。R06 v2 又取得一轮真实双机 8 秒合成源、严格 matched、独立终态和停服前分配释放证据。原报告仍按当时版本和范围保留，本 ADR 更新当前判断，不回写旧结果。

TASKS 的 P004 父项未随已批准决议改为 done，是状态遗漏。本轮修正为 **done（限定范围内按已批准录屏替代证据例外验收）**；历史未录屏、无可回放画面和覆盖限制继续保留。无需再次批准该例外。父项实际完成数仍是 5/7，不因修正文字新增一次测试。

## 决策

1. 原规范 §11 的最低媒体可行性已有真实证据：两台 Windows 持续视频、同一 PeerConnection 的模拟控制、真正 relay 媒体路径。可支持**技术可行性结论**，不能自动授予正式退出或产品发布。
2. R06 拆开记录：新版正常短会话的严格候选匹配和独立终态已实测；历史两次拒绝仍 NOT_REPRODUCED / NOT_DETERMINED。把它列为后续产品开发的剩余可靠性风险，**接受状态仍 PENDING**，不把“登记剩余风险”当成用户已接受。
3. 推荐提交**限定范围、附 R06 风险的退出方案**供用户决定。若用户明确接受，P006 可按限定媒体可行性验收、P007 可按正式决议收尾，而独立 R06 问题仍保持开放。批准之前 P006/P007 父项保持 doing，Phase 0 HOLD。
4. Phase 0 退出和 Phase 1 开发授权是两件事。退出获批后仍须明确批准 Phase 1 实施；规划文档、已完成 monorepo、预留模块均不构成启动许可。兼容引擎、多进程例外、驱动/路由及联网原型各自还须范围批准。
5. 保留 Tauri v2 + Rust + Vue 3 + TypeScript、DXGI/MF + 标准 WebRTC 库的现有成果。Sunshine Foundation / Moonlight V+ PC / EasyTier 的具体兼容目标按 ADR0015 独立评估；不以通用 H.264 或组网能力宣称协议互通。
6. 严格安全失败保持有效：不禁用 selected pair 校验，不放宽 UDP/会话白名单，不用 prflx 别名、静默切 relay-only 或自动重复配对来遮盖 R06。新的误接受、越权或凭据泄露会触发暂停相关连接能力并撤销风险例外的重新审查。
