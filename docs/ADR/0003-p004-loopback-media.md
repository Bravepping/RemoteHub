# ADR 0003：P0-04a 同机 WebRTC 视频验证

- 状态：采用，Windows 原生验收待执行
- 基线：`7fcbb519709a4655aa77aa4b8eca945c413891c2`；不改变 P0-03 CLI 或双机 P0-04 验收条件。

## 决策

1. 保留 Windows DXGI、CPU NV12、Media Foundation。专用阻塞线程在自己的线程上创建、使用和释放 DXGI/COM/MFT，通过 4 AU 有界队列送给 Tokio；队列满就终止该轮，不能静默丢 P 帧。以 P0-03 的实际 AU PTS 换算 90 kHz RTP 时钟。
2. 独立 `hub-webrtc` 锁定官方稳定版 webrtc-rs，单路 H.264 send-only，无音频/数据通道。使用真实协商与 RTP/RTCP；编码输出与提交给传输层、浏览器接收、解码和视频尺寸分别计数。
3. IPC 交换一次携带已收集候选的原生 offer / WebView2 answer，不开信令服务。只允许字面 IPv4 loopback 的 UDP host 候选；原生绑定 127.0.0.1，不使用 STUN/TURN 或 TCP。浏览器先过滤不符合条件的候选，原生仍独立检查。无可用 loopback 候选、选中路径不符或 H.264 不兼容就失败，不降级到局域网或公网。
4. P0-04a 需要显式启用 Windows Cargo feature 和内嵌应用资源。本机 `main` capability 限定命令，每轮必须经过原生对话框确认；请求期间只占用租约，不采集。成功拿到可信同机连接后才创建生产者。拒绝、停止、超时、连接/编码失败和关闭触发取消，释放线程和连接后方可重试。媒体只在内存中经过原生 WebRTC 轨道与接收窗，不写文件。
5. Windows WebView2 是否生成可用 loopback 候选属于待证实项。实验使用独立 WebView2 profile，并附加 Chromium 的回环允许参数与候选 mDNS 隐藏关闭参数，用于识别字面 127.0.0.1；这是范围严格限定的实验兼容性设置，非本机候选不会跨 IPC。参数是否被具体 WebView2 Runtime 接受仍待证实。不要求更改系统/防火墙或扩大连接范围。即使原生协商成功，仍需在 Win10 上真实解码至少 10 秒并完成清理回归，方可标记 P0-04a 完成。

## 兼容性与后续

默认构建不启用本实验；P0-03 文件实验保持独立。P0-04 仍要求两台机器，P0-05/06 未进入。未来双机应另行审查授权、信令和信任边界，不复用本 ADR 的同机限制作为远程认证。
