# ADR 0004：P0-04b 指定两台 PC 的有界局域网视频实验

日期：2026-11-21，基线5fb0867。状态：已实施并完成P004b双机实测；P004基线录屏未留存，父项仍保留证据差异。

用户已确认两台物理Windows电脑处于同一有线局域网且均可操作。当前机继续发送，第二台只接收；Windows10专业版22H2/x64、i5-11260H、16GB。不收集截图中的设备ID/产品ID，不把具体IP或设备身份写入公开证据。

## 范围与选择

新增默认关闭的 p004-lan 实验 feature；继续使用现有DXGI/MF、webrtc/rtc0.21.1、90kHz RTP、3AU有界队列和WebView2。保留P004a只绑定127及其测试。没有DataChannel、键鼠、账号、STUN/TURN或公网服务，不替代将来的持久身份/配对/ACL。

信令采用仅在用户明确启动后绑定指定本机RFC1918 IPv4的短时TCP端点，默认端口48604；只接受配置的另一台IP。不监听0.0.0.0，不做设备发现。接收端只连接用户指定地址。原生UDP同样绑定指定本机IP，并在webrtc Runtime socket边界双向过滤指定对端IP，拒绝其他来源/目的。

选择自动TCP交换SDP而非人工交换长SDP：减少跨机复制敏感临时凭据与操作错误。媒体仍是标准WebRTC DTLS/SRTP，未自研媒体协议。为了防止局域网篡改与重放，每轮生成独立随机128位级连接码，由用户在接收端输入；连接码不在网络传输或日志/报告保存。信令帧使用HMAC-SHA256，绑定版本、方向、随机会话nonce、严格递增序号、消息类型与完整SDP；常量时间验证。原生独立核对SDP的H264参数、DTLS fingerprint存在、候选/连接地址，拒绝非指定对端、其他媒体/data行与超长消息。DTLS继续验证已认证SDP中的证书指纹，不关闭证书验证。

连接码只可用于本次短测，等待连接最长120秒，最多5次接受尝试；成功认证后关闭listener，不接受新连接。双方都须在自己的原生窗口明确同意，本机窗口状态维护授权，不能只靠JS布尔值。输入限制和窗口ACL适用于所有调用方，无管理员豁免。

## 停止、并发与边界

配置媒体时长5–30秒，帧/字节上限保持原约束。TCP保留为原生控制/心跳租约，双方1秒心跳、3秒未收到有效消息或断线即取消；不是DataChannel。用户停止或关窗先撤销授权、取消信令/媒体、关闭PC并join线程。重复启动BUSY，停止幂等；故障不得留下采集。不同于普通JSON控制协议，所有控制帧同样校验HMAC、nonce、方向与序号。

接收端浏览器仅recvonly；将LAN/mDNS候选收敛到指定本机地址或留空，接收已认证且原生验证的答案后建连。真实selected pair远端若不是配置发送机立即停止。原始SDP/连接码不写磁盘；只保存非画面计数/候选类别与经过脱敏的IP匹配布尔值。明确区分编码/发送/接收/解码/呈现，关窗后未知的JS计数不补假值。

不自动修改Windows防火墙或网络类别。准备可审查、可移除、仅本程序/指定对端的规则脚本；实际需要时由用户批准/执行。将软件准备、单机受控网络测试与真实双机结果分别报告。P0-04b双机实际视频及启停验证后才能更新P0-04父任务；P0-05/06仍未完成。

## 验证与回退

先测IP/SDP白名单、MAC篡改/重放/方向、长度/超时、UDP双向过滤与取消；再原生同机回归和双机10–30秒运动、两端停止/关窗/断线，记录实际selected pair、帧数及释放。新依赖仅提升已锁定的hmac/sha2/uuid为直接依赖，核对官方API和许可；全workspace及all-feature检查。回退为关闭p004-lan feature，原P004a与CLI仍可独立运行。

参考：[webrtc0.21.1 Runtime接口](https://docs.rs/webrtc/0.21.1/webrtc/)、[RustCrypto hmac0.12.1](https://docs.rs/hmac/0.12.1/hmac/)。

## 首轮互通修正

首轮真实对端已通过认证，但接收端对库生成的应答报 OFF_HOST_ICE_REJECTED，发送端随之 SIGNAL_DISCONNECTED；0帧，资源释放。根因是库即使协商 rtcp-mux 仍在应答附加 component2 RTCP host 候选，初始校验仅接受 component1。v2仅在应答明确协商 rtcp-mux 时接受 component2，仍逐条限制相同指定IP/UDP/host；offer不放宽。真实库生成应答回归先复现失败、修复后通过，并覆盖其他IP/无mux/offer的负例。接收端原生协商错误同时直接传回界面，避免统一掩盖为 LAN_SIGNAL_FAILED。
