# ADR0019：Pinia状态所有权与有界只读IPC

日期2026-11-22；基线481e17e，本轮仅P1-04，不修改已有ADR。

1. 用真正Pinia管理普通产品壳的本机能力状态。每个Vue应用独立Pinia和DesktopApi依赖，不使用全局单例测试替身，不持久化状态。导航/弹窗的局部交互保持既有实现，不为未接入服务建假设备或会话。
2. DesktopApi目前只定义现有get_runtime_info读取；固定Tauri命令和严格运行时响应校验，不暴露可任意传字符串的invoke。既有bridge类型/函数兼容导出，实验采集/原生同意不变；不新增Rust命令、capability或实验权限。
3. 默认适配器真实调用Tauri；浏览器明确不可用，测试通过应用创建时显式注入同接口替身。没有产品mock模式、URL选择器或自动成功，也不把fixture当实测。
4. 读取5秒超时、手动重试、取消清定时器和监听。Pinia合并并发刷新，代次阻止取消/卸载后的迟到结果更新新状态。取消仅停止等待这个只读响应，不代表取消或停止媒体会话；没有实际事件源就不添加虚构订阅。
5. 错误只暴露固定码与中文消息；未知/畸形/超长响应拒绝，旧值清除。Pinia状态可被前端修改，不作为原生访问批准或会话权限；底层严格授权和候选校验继续由Rust负责。

备选的仅TS泛型不能校验实际IPC内容，普通模块全局ref会跨实例泄漏；均不采用。Pinia3.0.4精确锁定以复用现有Vue3.5，不扩至4.x新依赖机制；许可证/元数据与依赖审计独立留证。未来有正式设备/会话接口时另定合同及取消/停止/订阅资源所有权，不能把本轮只读取消当成该能力已实现。

回退用正常Git提交恢复App局部状态/旧bridge与锁，不重写历史或放宽安全。P1-04完成后等审查。
