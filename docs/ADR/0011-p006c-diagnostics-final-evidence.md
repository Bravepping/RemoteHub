# ADR 0011：严格候选诊断与接收端独立最终证据

状态：接受。基线GitHub main acd1910，工作树干净；本轮P0-06c-DIAG，仅离线和本地自动测试，无云端授权，不要求物理双机重测，不进入P0-07或Phase1。

## 问题与不变边界

两次旧DIRECT_SELECTED_PAIR_NOT_APPROVED来自原生本地/远端候选与各已验证集合的精确(endpoint,type)比较。旧记录不含具体选中端点或拒绝侧，不能归因于NAT、VPN、地址变化或类型表示；新诊断不能追填为旧实测结论。UDP白名单、过期/停止/配对授权、SDP类型/大小/媒体及旧本机/LAN/relay边界保持。诊断结果不能授予控制权限，不将host/srflx或同IP异端口视作相等。

## 决策

1. 诊断独立于放行：使用原生实际pair、已验证本地/远端集合及本次grant，记录固定枚举、候选计数、地址类别、同地址/同端口/同类型/精确匹配数；明确区分集合缺失、过期/作用域错误、地址范围拒绝、端口/地址变化、类型不一致、集合内无端点及不支持协议/类型。仅保留当前诊断、首次失败不被清理覆盖，无地址/端口实值、SDP、哈希可跨会话关联或凭据。
2. 精确匹配条件保持；增加集合scope绑定负例，不能通过跨会话集合匹配。SDP外prflx继续拒绝，只在诊断中标其类型，不加入运行白名单。
3. 新增版本化ReceiverEvidence本地契约，复用现有p006_save受限IPC的可选字段，无新增网络消息、云端接口、文件路径参数或输入能力。接收端在关闭PC/track前先保存live样本；失败则保留带原采样时刻的last_known或明确unavailable。原始错误保留为固定安全代码，不发送完整getStats原文。
4. 接收端独立写receiver-pre-close及receiver-final两阶段文件，后者追加真实控制关闭/PC/track及原生清理状态；数据结构和路径严格校验，不受WSS断线/短票到期影响，不将落盘诊断用作媒体/控制授权。原周期样本仍独立，旧final兼容，不把旧数据补成900。
5. 各清理步骤分开捕错，保存失败也必须继续关PC/track/原生任务。原生关窗立即cancel，通知前端限时保存；前端无响应则原生记录unavailable，不伪造浏览器最终getStats。进程被强杀/机器断电不保证JS执行，证据标缺失。

## 验证与兼容性

先策略/结构/隐私/跨会话单元和安全负例，再本地真实TLS/WSS、MF合成视频/Edge/control.v1，验证成功、主动停止及异常getStats/断线的独立JSON；不访问桌面或物理摄像头。完整旧功能回归与构建，明确区分fixture与真实本机传输、嵌入WebView2/新双机未测。若旧故障仍无法定位，提交最小化在线复现方案，不启动云服务。
