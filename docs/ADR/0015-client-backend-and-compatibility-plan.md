# ADR 0015：桌面客户端边界与具体兼容目标（提案）

日期：2026-11-22；基线 `7fde54e`。状态：**规划提案，未实施；兼容范围与进程/分发例外待批准**。固定继续采用用户要求的 Tauri v2、Rust、Vue3、TypeScript，不重建工程。

## 问题

当前WebRTC后端已实测，但没有Sunshine Foundation / Moonlight V+ PC协议互操作。v1.0“借鉴三件套、无第三方运行依赖”的范围与用户现在提出的具体兼容目标必须显式对齐。EasyTier网络承载与媒体协议是不同层；统一安装包也不证明只有一个进程或只有一个可见窗口。

本机候选安装包资源确认了Foundation和V+ PC名称，尚未验证发行来源/源码/API/许可。没有执行、联网或兼容原型。详见[离线评估](../COMPATIBILITY_INTEGRATION_ASSESSMENT.md)。

## 推荐方案

1. 现有DXGI/MF、标准WebRTC库、WebView2及control.v1继续作为默认可行性基线，不换库、不废弃已测Session，不用重构掩盖R06。
2. P1若获批，先整理薄客户端能力/会话边界：UI展示实际后端、路径、授权和可得统计，Rust拥有会话、原生权限和停止。不要为尚无稳定接口的三件套创建通用插件平台。
3. 对具体兼容目标优先评估受管理后端的最小原型：一个可见客户端协调必要进程、目标原生配对、配置和生命周期。只有确切目标API/来源/权限通过，且用户批准偏离“无外部运行依赖/单产品主程序”基线后，才允许引入。一个安装器的便利不能免除多进程治理和许可核验。
4. 若受管理V+窗口不能满足单UI呈现或权限隔离，评估经核验核心的嵌入/派生方案；FFI/原生呈现/崩溃隔离及长期维护另审。现在不从零重写兼容协议，不假定上游接口等于fork接口。
5. EasyTier仅作为未来可选网络承载提案。引入前需要明确节点/网卡/路由/驱动范围及实际选路观测；不把它当WebRTC↔目标协议转换器，亦不拿覆盖网身份代替会话ACL。
6. 无论后端，未经批准/已停止/过期不能采集或控制。现有WebRTC的候选范围、指纹/SDP验证及P004a本机限制保持；新后端必须提出等价权限与端点约束，不以“没有ICE”获得无限UDP权限。

## 兼容性与代价

提案不改变当前 wire protocol、依赖、IPC、能力返回、tauri权限、安装器或云端配置。Pinia/路由、托盘与后端管理接口都尚未实施；后续按P1任务逐项审查。旧实验构建与统计目录继续可复核，禁止将产品UI按钮绑定成自动启动旧采集/云配置入口。

如果C0目标合同要求原生三件套互操作，必须先评审兼容原型再确定后续范围；如果只批准P1管理现有后端，则清晰展示兼容未实现，不能默默放弃原目标。未来迁移需保持可切回已验证WebRTC构建、版本化统计和独立配置，不能覆盖用户既有三件套配置。

替代方案、验证门禁C0–C5、负例及选择触发条件均在兼容评估中记录。尚无A/B性能/维护成本测量，不保证任何路线更快、更便宜或具备完整分发合规性。所有实现须在Phase0正式退出和相应任务获批后开始。
