# P006c-DIAG 最小在线复现方案（未授权、未执行）

旧两次失败只能定位到原生精确端点/类型集合匹配失败，旧记录没有被拒绝侧和实际值。离线fixture能证明新诊断区分原因且不放行，但不能证明哪种组合在旧现场出现。不能由浏览器srflx/srflx推定原生实际pair，也不能以重试成功宣称故障消失。

额外线索：失败本端已发布集合仅srflx/relay，成功轮包含host/srflx/relay。若原生实际选中未发布的host，则即使浏览器报告srflx，也会被原有严格策略拒绝；离线已覆盖这一组合。旧数据没有实际失败pair/私有host发布批准状态，仍不能断言当时发生此机制，更不能直接把未发布host加入白名单。

本轮不启动阿里云、不索取新凭据或要求用户操作双机。以下只是供审查的后续最小范围，不构成授权：

1. 若用户另行批准，最多20分钟、现有专用WSS/TURN及已开放端口、最多4个Allocation、单会话；不改业务、coturn配置、FW/安全组或自启。新临时证书/邀请、到期停服和凭据清理机制沿用已审查方案，不复用已删除凭据。
2. 先用原Windows两机的相同网络/网卡设置，操作员合成源与现有接收前端做一次真实ICE协商，禁止自动真实桌面采集。采集actual pair的两侧固定原因、地址类别/类型、集合大小及相等关系计数、版本和时间，不保存原地址/端口、完整SDP、画面或密钥。若还需要原生WebView2窗口，仍由两端用户明确批准；不在本轮请求实施。
3. 只保留首次失败和一次成功对照，不无界重试。失败不打开媒体/控制权限；若正常匹配且合成视频开始，仅短时核对独立receiver-pre-close/receiver-final文件，不把它称作旧故障重现。
4. 如新日志仍仅显示“端点不在SDP”而无法区分来源，只提交证据；额外收集原地址/SDP、调整候选收集或白名单等均需新的设计与授权，不能现场绕过。未知情况继续拒绝。
5. 收尾先核对各Allocation Refresh0/实际租约回收，再停止专用服务且不自启、取消timer、清理两端/云端短票。无法确认立即释放时如实等待实际租约，不用停服务伪造释放；20分钟不够则按授权停止并报告证据不完整，不自行延期。

判定：拿到新版本一次原生拒绝的具体side/reason与相等关系才能归因本次新失败；若本次只成功，结论仅为“本次未复现”，不能追填历史两次根因。P0-07是否启动留待用户审查。
