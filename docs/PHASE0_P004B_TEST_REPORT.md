## 实现与准备

基线5fb0867，先提交ADR0004（dabb5fa）。新增显式 p004-lan feature，继续原webrtc/rtc0.21.1、DXGI/MF720p30/4Mbps与3AU有界队列；普通构建关闭LAN入口。发送/接收双角色，两端每轮原生确认、随机一次性码HMAC认证、UDP socket双向指定IP过滤、受限SDP/DTLS指纹校验、120秒配对等待、3秒控制心跳租约。原生源在认证及ICE连接后才启动，结束不保存视频。

## 首轮真实双机失败与修复

用户亲自操作两端确认。发送端authenticated=true，但接收端报 `LAN_SIGNAL_FAILED`，私有原生记录具体是 `OFF_HOST_ICE_REJECTED`；发送端 `SIGNAL_DISCONNECTED`。实际发送/编码均0帧，未启动采集，发送端原生资源已释放；接收端错误由用户读出，其完整清理记录未收取。脱敏发送端记录见 `artifacts/p004b/first-attempt.json`，不把接收端回报当作已看到画面。

原因：webrtc0.21.1在应答中附带component1/2两个host候选，初版校验仅允许component1。使用真实库生成的应答重现同样错误（components=[1,2]）；v2仅在应答有rtcp-mux时接受同一指定IP/UDP/host的component2，offer不放宽。修复后真实应答校验通过，外部IP、无mux、offer里component2仍拒绝。接收端原生错误也直接传到界面，另有认证坏应答的TCP回归覆盖。随后v2真实双机复测通过。
