# P006b 双机跨网络实验

本阶段为实验版：720p30 H.264 视频与真实 control.v1 共用一个 WebRTC PeerConnection，双方强制TURN；不执行实际键鼠输入。使用本次新版完整包，两台电脑都关闭旧实验窗口，再解压到可写的新文件夹。不要单独复制exe，旁边还需 `p006b-private.json`。此包含限时角色邀请，只供这两台自用电脑，不上传公开位置；CA公证书仅应用内使用，不安装系统证书。

发送端保持原宽带网络；接收端拔掉网线，连接使用4G/5G流量的手机热点，手机不要继续通过同一宽带Wi-Fi上网。选择各自实际有线/Wi-Fi地址，避免虚拟网卡地址。无需关闭防火墙或添加入站规则；两端主动连接本次批准服务器。

1. 发送端运行exe，角色选“发送屏幕（宽带电脑）”，勾选本轮同意，点击开始并亲自确认原生提示。该轮最长等待配对120秒。
2. 接收端运行同一新版exe，选“接收画面（热点电脑）”，输入发送端本轮64位配对码，勾选同意、开始并亲自确认。配对码只输入程序，不发聊天。
3. 两端连接后，确认接收端有持续变化的画面、1280×720、浏览器路径relay/relay且双端relay校验通过。实际选中路径未确认时不启动100条模拟事件。
4. 首轮让30秒自动结束，记录发送/ACK、未确认/异常与两端错误文字。源电脑的真实Rust接收/ACK、原生selected pair和对方回传统计会自动保存，不保存画面或坐标。
5. 首轮成功后每次重新配对、重新确认，等100/100后依次测试：接收端停止、发送端停止、接收端播放中关窗、关闭接收端热点连接。每轮等待双方回收完成，断网轮次恢复网络后再继续。

本地证据在程序旁 `artifacts/private/p006b`：progress为进行中快照，native-final为原生终态，final含浏览器关闭结果，window-close为关窗路径。发送端最后收到的浏览器快照可能早于接收端终态，不能简单用源帧数减最后快照判断丢帧。第一轮需对照Rust accepted_moves/acks_sent与浏览器sentMoves/ackReceived，均应100，ping/pong各1、连续1..101、pending/anomalies/rejected为0。

错误时只反馈固定错误文字和出现在哪一端，不发送配对码、私有配置或完整SDP。限时邀请过期需重新签发和换包，不能调系统时间或关闭校验。未完成双机实测与清理轮次时P006b保持doing，不以自动测试、云WSS入房或TURN Allocate代替真实视频验收。
